# 内网通信

面向可信局域网设备的聊天插件，使用宿主原生 TCP 服务收发文字、表情、图片和文件。主布局保持透明，主题、字体、控件及浮层材质由宿主注入，采用可调整的紧凑会话栏和底部输入区，发送按钮与字数计数位于输入框内；附近设备自动出现在会话栏。“连接与设置”由标题旁唯一的设置按钮打开，开启 / 停止通信在同一位置切换；手动连接、连接诊断、隐私和数据管理分别折叠收纳。顶部中间显示对端 IP 与连接状态。没有虚构联系人，消息只有收到对方保存后的回执才显示“已送达”。

## 两台设备开始聊天

1. 两台设备使用配套原生宿主和插件，在扩展中心授予 `messaging:lan` 并启用。最低宿主要求见 [清单](./extension.json)，按 [配套宿主](../../docs/publishing.md#固定配套宿主) 核对实际发布版本、源码提交与两端线协议；仅更新插件不能升级原生协议。
2. 两端打开已授权的插件，界面首次成功读取状态后自动开启局域网监听和设备发现；已有服务继续使用。附近设备随公告出现在会话栏，点选即可连接，无需填写 IP。真实协议握手完成后才成为最近会话；发现名单不写入历史。
3. 需要修改昵称时，点击会话栏标题旁的“连接与设置”；监听端口和手动 IP 操作位于“手动连接”折叠区。面板显示实际绑定的私有 IPv4 和端口，TCP 默认端口为 `45873`；端口被占用时先停止，再更换端口。也可填写对方显示的 IP 和端口，点击“连接设备”。
4. 选择会话，在底部输入消息，点击发送或按 `Enter`；`Shift + Enter` 换行，输入法组合期间的回车不发送。“等待送达回执”表示尚未确认送达，对端原子保存并回传 ACK 后才显示“已送达”。

只接受数字形式的私有、回环或允许的本地链路 IP，不接受域名或任意 URL，不扫描 IP。发现使用 UDP `45874` 在同网段广播，附近记录定时过期；不自动建立聊天连接。默认监听优先选择可用的私有默认路由；VPN 等接管该路由时回退到已启用的私有网卡，发现公告发往所选网卡的子网广播地址。未选出可用私有 IPv4 时仅绑定回环地址，不能供其他设备连接。连接和发现仍受默认网卡、系统防火墙和网络隔离策略影响；跨网段、VPN 和同机多进程可能无法发现，仍可手填 IP。插件不修改防火墙、提权或调用 Shell。

## 本机回环测试

在“连接与设置”面板展开“连接诊断”，点击“开始回环测试”，无需切换页面。原生服务会在 `127.0.0.1` 的随机端口创建节点和回环助手，通过真实 TCP 握手、收发与 ACK 验证当前设备的通信链路；不需要另一台设备，也不是浏览器模拟。握手完成后自动选中“回环助手”，可测试文字、表情、图片和文件，助手会回送收到的内容。回环模式不发送发现公告；结束回环测试后，点击“开启通信”可恢复局域网模式。

启动另一连接模式会停止当前服务连接，已有联系人和历史仍保留。回环地址不会暴露给其他设备；此测试不能代替两台设备、私有网卡路由、防火墙或正式安装包验收。点击“停止通信”或“结束回环测试”结束本次测试，并回收助手的临时数据；回环连接同样遵循窗口与撤权回收规则。

## 表情、图片与文件

- 点击“表情与表情包”将 Unicode 表情插入草稿，或发送独立的大表情消息。大表情无需下载远程素材。
- 点击“发送图片”或“发送文件”，由原生文件对话框选择要发送的文件；界面和远端都拿不到系统路径。图片使用实际内容解码校验，支持 PNG、JPEG、WebP；其他格式可以作为普通文件卡片传输。
- 图片消息只显示图片与送达状态，缩略图按原图比例显示，列表优先加载最近图片的轻量缩略图，并保留有限缓存。单击展开清晰预览，预览随图片比例适配可用空间；使用紧凑工具栏、滚轮、触控板双指捏合或键盘缩放、拖动平移及复位。图片和普通文件的操作统一放在右键菜单，也可用 `Shift + F10` / 菜单键打开；图片提供“查看图片”“另存为”，文件只提供“另存为”，卡片保留名称和大小。另存时由系统对话框选择路径，接收内容不会自动打开或执行，取消选择或另存不会冒充发送 / 保存成功。
- 图片最多 8 MiB，普通文件最多 1 GiB，均须非空。普通文件流式传输和校验，不把整个文件载入内存；未完成的接收临时文件不会冒充已送达。主节点附件缓存最多 2 GiB；回环助手有独立测试暂存，同样受 2 GiB 单节点上限约束，每次完成回送后回收，停止测试时再次清理。缓存满时会明确报错，可清理历史后重试；淘汰或删除历史会清理未被引用的附件，仍被在途操作使用的内容在使用结束后由后续清理回收。文字和表情正文最多 8192 UTF-8 字节；允许换行与制表符，拒绝其他控制字符。精确存储、阶段超时、协议和图像额度见 [宿主 LAN 边界](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md#局域网通信)。

选择文件后，在对应的图片或文件气泡内显示准备、校验、发送或接收进度，包括本阶段已处理字节、总字节和百分比；发送在右侧，接收在左侧。传输开始时显示附件占位，历史记录到达后沿用同一条消息，不重复插入；未完成的附件不能预览或另存。准备阶段流式复制并计算散列，发送与接收阶段统计实际读写字节；切换阶段时从该阶段的进度开始，不把本机准备冒充网络发送。传输时独立读取进度，不会等待发送请求结束才刷新；字节写完仍需等待对方原子保存和回执，不能据此认定已送达。

传输期间可点击“停止传输”，原生服务会停止本次服务与连接，保留已有历史和草稿；它同时影响共享服务的其他窗口。已完成的发送不回滚，未收到送达回执时先核对对方记录，再决定是否重新连接并发送。

## 调整聊天布局

拖动会话列表右侧分隔条可调整会话栏宽度，拖动输入区上方分隔条可调整输入区高度。使用 `Tab` 聚焦分隔条后，左右方向键调整宽度，上下方向键调整高度；按住 `Shift` 使用较大步长，`Home` / `End` 调到当前窗口允许的最小 / 最大尺寸，双击恢复默认。拖动时按 `Escape` 取消本次调整。

布局尺寸通过会话检查点保留，界面重建后恢复，并随窗口空间约束到可用范围；窄窗口收起会话栏分隔条，保留聊天空间。“连接与设置”面板随内容收紧，受可视窗口高度限制，内容较多时在面板内滚动。

草稿检查点临时写入失败时会保留待写内容，有限重试；持续失败时请保留页面，待宿主保存结束、重新激活页面或打开“连接与设置”后重试。未完成的 IP / 端口编辑作为表单草稿恢复，实际启动或连接仍严格校验地址和端口。移除联系人前会确认同时移除其未发送草稿，其他会话草稿保留。

## 信任边界与数据

通信通过局域网 TCP **明文传输**，没有端到端加密或远端身份认证，昵称和节点身份由对方自行声明。仅连接可信设备，不传输密码或其他敏感信息，不会上传云端。文件能力仅限用户主动选择的发送和另存；插件不接收远端文件路径，不自动打开文件，也不提供命令执行能力。

`messaging:lan` 是必需能力，涵盖监听、附近设备发现、连接、消息和附件传输、本服务的联系人、历史及受限附件缓存。它不授予通用 HTTP、任意文件读取或凭据能力。授权、读取状态和导入检查点本身不启动服务；打开已授权的插件界面会在首次成功读取状态后开启监听与发现，不自动连接或发送。明确停止后，本次界面不再自动启动。

监听由原生服务持有，切换到其他页面仍能收信；界面只在可见时每两秒读取状态，传输期间每半秒单独读取阶段进度，隐藏和卸载后清理轮询。点击“停止通信”或“结束回环测试”、最后一个使用此服务的原生窗口关闭、撤销授权、更换或卸载插件、退出应用时，会停止监听并回收本次服务创建的连接与工作线程。

后台刷新不禁用按钮或覆盖输入，旧响应不倒退手动操作与授权状态。普通操作只锁定当前动作的按钮，服务请求仍按原有顺序准入；联系人和已加载图片保持稳定，新增消息复用已有消息节点，送达回执单独更新状态文字。读取失败时保留最后有效历史并显示错误，随后自动重试，连续相同失败不重复提示。

联系人最多 64 项，连接最多 16 个，消息最多保留最近 500 条，历史编码存档最多 1 MiB。联系人、历史与附件按插件 ID 隔离保存在宿主应用数据目录，历史采用独立 schema 与原子写入，不属于插件 KV 或笔记备份。损坏、未来版本、超限、链接或非普通文件会拒绝覆盖并保留原件；隔离恢复状态禁止服务。宿主支持读取原有 schema 1 文本记录，下次修改时原子升级到 schema 2，不能通过删除用户数据修复升级。

界面支持搜索、未读计数、离线会话、重连及移除离线联系人。会话标题的更多菜单提供“清空历史消息”：确认后删除当前会话的全部本机文字、图片和文件消息，并回收不再被其他消息引用的本机附件缓存；仍在使用的附件在操作结束后按缓存回收规则清理。联系人、未发送草稿、其他会话、对方电脑记录、原始源文件及另存到其他位置的文件保留。“连接与设置”中的数据管理仍可清空本机全部会话历史。确认区可按 `Escape` 取消，取消或完成后恢复到原操作入口。

会话标题的更多菜单还提供导出，由 Wasm 校验并生成纯文本产物，再由宿主弹出保存对话框；图片和文件以名称、大小的文本标签保留，不嵌入附件字节。单次导出连同标题、时间及省略说明最多 200 KiB，超出时明确说明省略了多少条最早消息。导出不会发送或清空草稿，临时超过发送限额的草稿也不阻止导出已有会话。

未发送草稿通过宿主检查点报告，连续输入合并为串行写入，发送期间的新编辑不会被较早的发送结果清空。导入会话或重新打开界面不会自动发送消息或连接联系人；界面打开时仅自动启动局域网监听和发现。未知版本或损坏的检查点保留原件，界面暂停业务修改及自动启动，仍可读取与导出已有聊天记录；先从宿主工具导出原会话，再使用匹配版本处理。

## 开发与验证

以下命令从市场仓库根目录运行：

```sh
cargo test --locked --manifest-path plugins/lan-chat/Cargo.toml --target-dir target/lan-chat-native
cargo clippy --locked --manifest-path plugins/lan-chat/Cargo.toml --target-dir target/lan-chat-native --all-targets -- -D warnings
node --test plugins/lan-chat/ui/main.test.mjs
cargo build --locked --release --target wasm32-unknown-unknown --manifest-path plugins/lan-chat/Cargo.toml --target-dir target/lan-chat
```

手写 [`smoke.json`](./smoke.json) 检查真实 Wasm 的双语入口、安全文本与附件标签导出、非法状态拒绝；界面回归检查菜单、回执、后台失败、授权 / 发送竞争及检查点。宿主 `extension_lan` 测试验证真实回环 TCP、附件与本机回环助手、持久历史和生命周期，不能用界面替身代替真实服务测试。两台设备、系统对话框、桌面窗口与防火墙仍需单独验收，见 [测试规范](../../docs/testing.md#固定原生服务验收)。

服务统一通过 `starter.services.request("lan", request)` 调用，请求和额度以宿主 SDK 与 `extension_lan.rs` 为准；界面不直接使用 WebSocket、TCP、浏览器存储或原生 IPC。新消息协议要求双方使用同一配套实现，旧协议明确拒绝；工具准备、真实 Wasm 校验入口见 [开发指南](../../docs/development.md)。

界面、消息状态、确认操作、反馈与会话导出均跟随宿主中英语言切换，切换时保留当前输入、焦点和会话。昵称及消息正文保持用户原文；字体、明暗主题和语义颜色由 SDK 注入。
