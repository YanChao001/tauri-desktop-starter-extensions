# 局域网信使

这是使用宿主原生 LAN 服务的真实纯文本聊天插件。自定义 HTML / CSS / JavaScript 界面包含联系人和会话列表、消息区、草稿、昵称、监听设置与手动 IP 连接；不展示虚构联系人，也不把写入 TCP 当作已经送达。

## 两台设备开始聊天

1. 两台设备安装当前宿主和插件，在扩展中心审阅并授予 `messaging:lan`，再启用插件。
2. 各自填写昵称，点击“开启监听”。页面会显示实际绑定的本机私有 IPv4 和端口，默认端口为 `45873`。端口被占用时可在监听前更换。
3. 在其中一台输入对方页面显示的 IP 和端口，点击“连接设备”。联系人只有在双方完成真实协议握手后才会出现。双方均需先监听。
4. 选择联系人，输入文本，点击发送或按 `Ctrl / ⌘ + Enter`。`Enter` 可换行。消息显示“已写入连接，等待回执”，对方原子保存后回传 ACK，才显示“已送达”。

只接受数字形式的私有或回环地址，不接受域名或任意 URL，不扫描网络。默认监听地址通过本机路由选择；没有可用私有 IPv4 时仅绑定回环地址，此时只能在同一台设备使用。连接受系统防火墙和网络隔离策略影响，插件不会修改防火墙、提权或调用 Shell。

## 信任边界与数据

消息通过局域网 TCP **明文传输**，没有加密或远端身份认证，昵称和节点身份由对方自行声明。仅连接可信设备，不传输密码或其他敏感信息。本插件只收发文本，不读取、发送或接收文件，不提供远端文件路径与命令执行能力；不会上传云端。

`messaging:lan` 是必需能力，涵盖监听、连接、文本消息及本服务自己的本机联系人和历史。没有通用 HTTP、文件或凭据权限。仅授予能力不会自动开启监听，读取状态也不会开启监听。

监听由原生服务持有，切换到其他页面仍能收信；界面只在可见时每两秒读取状态，卸载后清理轮询。点击“停止监听与连接”、最后一个使用此服务的原生窗口关闭、撤销授权、更换或卸载插件、退出应用时，会停止监听并回收本次服务创建的连接与工作线程。

联系人最多 64 项，连接最多 16 个，消息最多保留最近 500 条且整体编码存档不超过 1 MiB。消息正文每条最多 8192 UTF-8 字节；界面显示字节数。历史和联系人按插件 ID 隔离，以宿主应用数据目录内固定哈希文件名原子保存，关闭连接仍保留数据。未来版本、损坏、超限、链接或非普通文件都会拒绝覆盖并保留原件；隔离恢复状态禁止服务。

界面支持搜索、未读计数、离线会话、重连、确认后清空历史及移除离线联系人。导出当前会话使用 Wasm 校验并生成纯文本产物，之后仍由宿主弹出保存对话框；单次导出最多约 200 KiB，超出时明确说明省略了多少条最早消息。未发送草稿通过宿主检查点报告，导入会话或重新打开界面不会自动发送消息、恢复连接或开启监听。

## 开发与验证

插件与其他市场项目使用相同 Cargo 构建流程：

```sh
cargo test --locked --manifest-path plugins/lan-chat/Cargo.toml
cargo build --locked --release --target wasm32-unknown-unknown --manifest-path plugins/lan-chat/Cargo.toml --target-dir target/lan-chat
```

`smoke.json` 验收真实 Wasm 的会话引导和安全导出，不伪造 LAN 通信。真实 TCP 双端收发、回执、昵称同步、历史重开、取消回收、协议与文件边界由宿主 `extension_lan` 服务回归测试验证。浏览器界面检查使用明确标识的服务边界替身，不代表真实桌面网络或各平台防火墙已验收。

服务 SDK 统一调用 `starter.services.request("lan", request)`。操作包括 `status`、`start`、`stop`、`connect`、`send`、`markRead`、`nickname`、`clearHistory`、`forget`，均返回最新状态；具体请求字段和严格验证以宿主 `extension_lan.rs` 为准。界面不直接使用 WebSocket、TCP、浏览器存储或原生 IPC。

当前界面以中文为主，Wasm 引导和产物入口同时支持宿主中英语言；字体、明暗主题和语义颜色由 SDK 注入。
