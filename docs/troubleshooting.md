# 市场排障手册

先区分客户端读取、包安装、本地构建与远端发布。记录宿主版本、市场提交或 Release、目录修订、插件 ID / 版本和稳定错误码，保留脱敏日志。发布步骤见 [发布指南](./publishing.md)，安全报告见 [安全规范](./security.md#漏洞与密钥事件)。

## 客户端错误

| 错误码                   | 典型原因                                                | 处理方法                                                |
| ------------------------ | ------------------------------------------------------- | ------------------------------------------------------- |
| `MARKET_NOT_CONFIGURED`  | 仓库或受信公钥未配置                                    | 核对宿主配置与目标仓库、公钥，再重新构建                |
| `MARKET_INCOMPATIBLE`    | 已验签目录使用不支持的 schema                           | 使用配套宿主与目录；签名有效不表示协议兼容              |
| `MARKET_EXPIRED`         | 已签名目录到期                                          | 核对设备时钟；维护者以更高 revision 续签发布            |
| `MARKET_INVALID`         | 签名、结构、时间、大小、哈希异常，或目录回退 / 同号替换 | 保留目录证据，核对信任源、附件、修订和时钟              |
| `MARKET_UNAVAILABLE`     | 网络、超时、缺附件或本机信任记录 I/O 失败               | 核对公开 Release、完整附件、网络与应用数据目录后重试    |
| `MARKET_CHANGED`         | 所选包或来源收据与当前目录不符                          | 刷新后重新审阅并下载，不复用旧收据                      |
| `EXTENSION_INCOMPATIBLE` | 包 / API、最低宿主或注册表版本不兼容                    | 按失败阶段选择配套包 / 宿主；旧注册表使用应用内归档流程 |

旧客户端可能统一显示“市场目录或扩展包校验失败”。先确认正在运行的原生程序版本；前端刷新不能替换 Rust 进程。

### 新目录在旧宿主显示 MARKET_INVALID

旧宿主可能在解析新权限或图标时失败，尚未进入包的 `minHostVersion` 检查。先按 [固定配套宿主](./publishing.md#固定配套宿主) 取得包含所需能力的原生构建，正常退出旧进程，启动新构建后刷新市场。不要改公钥、放松枚举或关闭验签；本地新源码也不代表安装包或线上目录已发布。

### 已验签但仍然不兼容

核对目录 schema、包格式、API、视图与最低宿主，精确版本见 [固定配套宿主](./publishing.md#固定配套宿主)。协议升级须从配套源码重建并签名，不能只修改 JSON 版本号或提示文案。

### 某条目仅显示需要新宿主

0.1.6 起可隔离最低宿主高于当前版本的未来条目：可理解的条目保留预览，未知正文只提供只读摘要，均不允许下载或安装。升级配套宿主后刷新。此机制保留完整信任校验，不适用于旧程序或当前版本的损坏清单；完整条件见 [兼容与演进](./architecture.md#兼容与演进)。

### 自定义界面打不开或只看到旧布局

核对原生宿主的 HTML 协议 / SDK、已安装插件版本及 UI 哈希。同一开发版本号不保证实现相同；重编、重启宿主并安装新包后重试。连接失败可从“扩展工具”重载，已报告的字段与检查点会恢复，不重新初始化 Wasm。

持续失败时检查 UTF-8、`ui.document` 引用、哈希、授权和 CSP，保留注册表与私有存储。首屏骨架反映真实加载，前台握手停滞可重试；已展示但正文异常仍应检查作者脚本。工具入口、默认样式、语言 / 主题与 select 行为见 [自定义界面开发](./development.md#自定义界面开发)，不伪造握手或放开远程脚本。

### 已推送分支但市场仍是旧内容

客户端只读取配置仓库的公开 latest Release。检查 `main` 合并、发布工作流、草稿公开状态以及目录和全部包附件；分支、PR、本地子模块与离线验签均不会更新线上目录。可从市场根目录只读检查，仓库名以 [listings.json](../listings.json) 为准：

```sh
gh release view --repo YanChao001/tauri-desktop-starter-extensions --json tagName,isDraft,isPrerelease,targetCommitish,publishedAt,assets
gh workflow list --repo YanChao001/tauri-desktop-starter-extensions
```

显式刷新可重新获取目录；网络失败时保留的旧展示不保证下载资格，过期目录不能安装。

### 签名有效但包校验失败

完整 JSON 包的 `packageSha256` / `packageBytes` 与内含 Wasm 的哈希 / 大小都须匹配。常见原因是签名后重打包、格式化 JSON、上传旧附件或清单和模块不符。

运行 `node scripts/verify.mjs <发布目录>` 核对全部包。签名前还会对照已审核清单、HTML 和规范包字节，拒绝链接路径、无效 UTF-8、非规范 Base64 与超限输入。失败时保留原目录，从审核过的源码重建并发布更高修订，不覆盖公开附件或客户端期望哈希。

### 时间、过期与目录回退

核对设备 UTC 时间；时区仅影响显示。已到期为 `MARKET_EXPIRED`，签发过远或有效期窗口异常为 `MARKET_INVALID`。宿主跨重启保留最高修订及 payload 摘要，同号改日期、改推荐或重签也会拒绝。按 [有效期与续签](./publishing.md#有效期与续签) 发布更高修订，不删除信任记录或倒拨时钟。

## 原生服务与插件功能

### 新权限或服务不可用

核对已安装清单、实际授权、启用状态和原生宿主实现，按 [固定原生服务](./development.md#固定原生服务) 区分各项能力；可选网络授权不应阻塞本机图库。禁用、撤权或替换后重新打开当前包，不复用旧页面句柄。停止等待不代表已经保存、发送或下载的操作回滚，重试前核对实际状态。

### LAN 监听或连接失败

在“连接与设置”面板按 [内网通信步骤](../plugins/lan-chat/README.md#两台设备开始聊天) 选择局域网，在双方开启监听并使用对方实际显示的数字私有 IPv4 与端口。路由未选出可用私有 IPv4 时仅绑定回环地址；`127.0.0.1` 指向本机。端口占用时停止后换端口，另行检查路由、防火墙和无线隔离，插件不会修改这些设置。只验证本机时可切换“本机回环”，点击“开始回环测试”，无需填写另一设备地址。

联系人在真实握手后出现；“已写入连接，等待回执”尚未送达，只有对端原子保存后的 ACK 才确认。缺回执时保留状态，核对对方历史后再决定重发。协议明文且无远端身份认证，不传输秘密。双方须使用 LAN wire v2 端点；该协议已随宿主 `0.1.7` 发布，当前插件另需 `0.1.8` 的共享界面规则，仅替换插件不能升级旧宿主的协议或 SDK。核对 [配套宿主](./publishing.md#固定配套宿主)。

图片选择后无法发送时检查真实格式与大小；图片最多 8 MiB，PNG、JPEG、WebP 以内容解码校验，改后缀不能绕过。普通文件最多 1 GiB。附件过大时按图片 / 文件分类检查字节及图片像素额度；缓存满时清理不需要的聊天历史，释放未被引用的附件；传输中断时再检查对端连接、网络进展和超时，不把所有附件问题归因于 IP 或端口。未收到回执时先核对对方记录，再显式决定重试。

文件卡片缺预览不等于传输失败；普通文件只支持“另存为”，不会自动执行。系统另存取消后不显示保存成功；附件不可用或缓存达到额度时保留记录并按反馈处理，勿删除整个用户目录。

### 切换页面后仍然收信

导航和 iframe 重载保留已开启的原生连接。点击“停止监听与连接”可停止；最后一个服务窗口关闭、撤权、替换、卸载或退出也会回收，历史保留。完整生命周期见 [内网通信说明](../plugins/lan-chat/README.md#信任边界与数据)。

轮询不应禁用输入或覆盖新草稿；出现卡顿、状态倒退时核对内网通信包与 SDK 版本，反馈中区分后台查询和手动请求，并记录延迟 / 乱序条件。

### 图源加载、预览或下载失败

先按 [固定配套宿主](./publishing.md#固定配套宿主) 核对插件版本；旧开发包的供应商接口不能靠删除图库恢复。区分图源 HTTP 请求、Wasm JSON 解析、图片获取、句柄失效与解码 / 额度拒绝。API 改版、限流或错误图源会拒绝替换列表；旧结果仍标记原成功图源与筛选。关键词或明确分类不足 24 张、甚至零结果都按真实数量显示；只有随机发现缺少足量不同图片时才会在有界补齐后报错。可稍后刷新或切换来源，接口 200 不代表图片可直达与解码。

按 [网络连接](../plugins/wallpaper-browser/README.md#网络连接) 核对宿主“设置 → 网络”中的 direct / system 选择及插件独立授权。壁纸库继承宿主连接方式，不再提供局部切换或恢复检查点中的旧模式；宿主选择系统代理但插件未获 `network:system-proxy` 时仍直连，兼容规则见 [宿主扩展指南](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md#来源与授权)。直连拒绝 Fake-IP 和其他非公网 DNS 结果；代理排除时也执行直连检查。浏览器能打开原站不表示原生使用相同传输，不关闭 TLS、SSRF 或重定向限制。

图片原站可能移除文件、要求 Cookie、跳转或返回不支持格式。资源有绑定与有效期，失效后重新获取，预算满时释放无用资源；不复用会话句柄。另存取消属于正常结果。分别记录图源加载、预览、原图另存与图库导入的结果，真实环境和替身的范围见 [服务验收](./testing.md#固定原生服务验收)。

### 图片已加入图库但不是原始文件

“加入图库”重绘压缩，“下载原图”另存已验证的原文件，应用背景仅影响本应用。图库满或设置 revision 冲突时保留原数据，刷新后重新选择。移除正在使用的背景需确认并恢复纯色，不清空其他偏好；操作见 [壁纸说明](../plugins/wallpaper-browser/README.md#图源预览与资源)。

### 游戏没有声音或返回后暂停

Web Audio 需用户点击解锁，检查静音和系统音量；无音频支持仍可游玩。失焦、隐藏和长帧会暂停，返回后手动继续，不补算离开时间。保存取消保留棋局；长期保留使用宿主会话导出，纪录保存不是棋局备份。

## 本地构建与真实 Wasm 校验

### 找不到 `extension-tool`

`STARTER_EXTENSION_TOOL` 应为真实宿主工具的绝对路径，不能指向桌面主程序或重命名脚本。子模块可自动探测宿主 debug 路径，独立检出需显式设置；按 [工具准备](./development.md#准备宿主校验工具) 构建。

宿主源码变化后重编工具。未知 fixture 断言或清单字段通常应先核对实际宿主提交，不删除断言迎合旧工具。

### Rust 目标或插件产物缺失

在市场目录使用 [锁定工具链](../rust-toolchain.toml) 运行 `rustup target add wasm32-unknown-unknown`，检查 `RUSTUP_TOOLCHAIN` 没有覆盖选择。`build.json` 的文件名须对应 Cargo 实际库名，产物位置以 target-dir 为准。

直接修复锁文件、格式、源码或宿主报告的校验阶段，不移除 `--locked`、删除锁文件、复制旧 Wasm 或跳过真实运行。

### 已存在相同修订目录

`Release directory already exists` 表示 `artifacts/market-<revision>` 已存在。保留旧产物，换未使用的修订重新构建。正式发布还须高于历史及客户端已见修订；改目录名不会改变签名 payload。

## CI 与生产发布

### 宿主工具准备长时间没有进展

展开 `host-tool` 步骤，用日志时间戳区分 APT、pnpm 和 Rust 编译。APT 的镜像 `Ign` 应先按网络下载排查；[宿主工具 action](../.github/actions/host-tool/action.yml) 使用官方 HTTPS 镜像及有界超时 / 重试。保留完整失败日志再重跑，不跳过系统依赖或 Wasm 验证。

### PR CI 使用了旧宿主或无法检出 ref

按 [固定配套宿主](./publishing.md#固定配套宿主) 核对 `STARTER_HOST_REF`、本次 `host_ref` 与 Actions 摘要 SHA；发布输入不影响 PR CI。生产拒绝非完整 40 位宿主 SHA，未推送、拼错或无读取权限的 ref 无法检出，不能以本机产物替代。

发布 `revision` 必须是十进制正 `u32`，拒绝空白、科学计数、十六进制和越界值，前导零会规范化。各变量和触发范围以工作流为准。

### 生产 Secret 缺失或与公钥不匹配

`Signing key does not match public-key.txt` 表示私钥缺失或与受审核公钥不匹配；无效 PEM、不可读 `MARKET_KEY_FILE` 会直接报告解析或文件错误。按具体错误检查 Secret、仓库外文件及密钥配对，不输出密钥值。普通 `check` 不验证生产 Secret；真正轮换按 [公钥轮换](./publishing.md#下架回退与公钥轮换) 配套执行。

### revision 重复或发布目标 SHA 错误

| 错误                                                        | 处理                                                                                 |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `Market revision must increase`                             | 选择高于完整非草稿 Release 历史与客户端已见值的新修订，从构建开始执行                |
| `Release source must be a complete 40-character commit SHA` | 核对市场源码的 `GITHUB_SHA` / `MARKET_SOURCE_SHA`，前者优先；不用宿主 SHA 或短 SHA   |
| `Release tag does not match the reviewed source commit`     | 核对标签最终 commit；`--target` 不会改指向，使用未占用的更高修订或按草稿恢复流程处理 |

历史 / 标签 API 错误会阻止发布，不能忽略为“不存在”。不强制移动已公开标签；完整检查顺序见 [生产发布](./publishing.md#actions-生产发布)。

### 上传失败或只看到草稿

先核对日志和草稿附件，脚本不会自动恢复现有草稿或覆盖附件。按 [生产发布](./publishing.md#actions-生产发布) 处理后重试，不公开不完整草稿。已经公开的问题使用更高修订修复或下架，删除 Release 不会卸载用户副本。

## 数据保留与求助

市场读取或下载失败不需要删除注册表、私有存储、凭据或信任记录。旧开发版注册表只使用宿主确认归档流程，未来 / 损坏数据保留原件，不在应用使用目录时从外部搬动它。

普通 bug 提供版本、提交 / Release、错误码、复现与脱敏日志；安全问题按 [私密报告渠道](./security.md#漏洞与密钥事件) 处理。交付记录实际检查与未验证范围，浏览器替身、离线 fixture 和 CI 配置不代表真实桌面或线上发布成功。
