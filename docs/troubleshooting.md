# 市场排障手册

先区分客户端读取、包安装、本地构建和远端发布的失败，再处理对应边界。记录宿主版本、市场提交或 Release 标签、目录修订、插件 ID / 版本和稳定错误码；不要上传用户数据、密钥或完整会话。发布流程见 [发布与维护](./publishing.md)，权限和报告渠道见 [安全规范](./security.md)。

## 客户端错误

| 错误码                   | 典型原因                                                                    | 处理方法                                                                                   |
| ------------------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `MARKET_NOT_CONFIGURED`  | 宿主没有有效仓库或受信公钥                                                  | 由应用维护者核对宿主市场配置，与 `public-key.txt` 和目标仓库一致后重新构建；不填写随机公钥 |
| `MARKET_INCOMPATIBLE`    | 已验签的目录使用不支持的 schema                                             | 核对配套宿主和真实 latest 目录，重新构建并发布当前协议；签名有效并不表示协议兼容           |
| `MARKET_EXPIRED`         | 当前协议的已签名目录到期                                                    | 校准设备时钟；若确实到期，由维护者以更高 revision 续签并发布，刷新后重试                   |
| `MARKET_INVALID`         | 签名、目录结构、时间范围、包大小或哈希不一致，或目录回退 / 同号替换         | 保留错误与目录证据，核对信任公钥、附件、发布修订和时钟，不跳过校验                         |
| `MARKET_UNAVAILABLE`     | 网络、HTTPS、GitHub 状态、下载超时、缺少附件或本地信任记录的 I/O 失败       | 确认 Release 已公开、附件完整、网络和应用数据目录可用，再刷新；此错误可重试                |
| `MARKET_CHANGED`         | 页面所选包或来源收据已经与当前目录不同                                      | 刷新市场，重新审阅并选择当前包；不要重用之前下载的来源收据                                 |
| `EXTENSION_INCOMPATIBLE` | 扩展包/API 或 `minHostVersion` 不适合当前宿主，或客户端扩展注册表版本不兼容 | 区分具体发生阶段；更新配套包或宿主。旧开发版注册表按宿主扩展指南的应用内归档流程处理       |

错误码由原生边界返回。旧客户端可能将不兼容或过期显示为统一的“市场目录或扩展包校验失败”；先确认运行的原生程序确实包含最新诊断，刷新前端页面不能替换仍在运行的 Rust 进程。

### 新目录在旧宿主显示 MARKET_INVALID

上一轮四款插件最低宿主为 0.1.5；当前本地源码中的壁纸库 1.0.3 最低要求 **0.1.6**，其余三款保持 0.1.5。0.1.5 及更旧宿主使用闭集权限 / 图标枚举，不认识新目录值时可能在解析 schema 2 目录时返回 `MARKET_INVALID`，即使公钥与签名正确。包的 `minHostVersion` 检查位于此后，不能让这些旧二进制识别新协议字段。

本轮本地源码与构建包尚不表示新市场目录或宿主安装包已发布。获取经过审阅的配套宿主，按开发指南重新构建原生程序，正常退出旧进程后启动新构建，再刷新市场。浏览器开发服务器、热更新或刷新前端都不能替换 Rust 实现；也不要通过改包版本、换公钥、放松枚举或关闭验签规避。确定宿主提交的流程见 [固定配套宿主](./publishing.md#固定配套宿主)。

### 已验签但仍然不兼容

当前协议使用目录 schema 2、包格式 3 / API 2、视图版本 2。旧 schema 1 目录即使公钥正确且签名有效，仍会被新宿主拒绝。维护者需要从配套源码重新构建所有包、生成 schema 2 目录并生产签名发布，不能只改客户端提示、修改 JSON 版本号或允许旧 DTO 进入执行边界。

反过来，新目录也不保证老宿主能够理解；清单 `minHostVersion` 只是包的最低版本声明，不能给旧宿主补上新协议实现。跨仓库更新顺序见 [固定配套宿主](./publishing.md#固定配套宿主)。

### 某条目仅显示需要新宿主

0.1.6 起，已验签 schema 2 目录可隔离严格有效且最低宿主高于当前版本的未来清单正文，其他条目仍可使用。可完整理解的未来条目保留预览但原生下载拒绝；无法理解正文的条目只显示 ID、名称、版本、最低宿主和分类摘要，没有下载或安装入口。升级到实际包含所需能力的宿主后再刷新，不能通过修改 `minHostVersion` 或手工下载规避。

如果最低宿主没有高于当前版本，未知权限、图标或清单结构仍属于目录错误；坏签名、未知 schema、过期或异常元数据也不会被隔离。重复 JSON 字段、身份、附件来源、大小、哈希、UI 元数据和时间均保持严格检查，隔离条目也受完整原始签名 payload 的同修订摘要保护。这项新行为不会自动出现在 0.1.5 或更旧程序中，完整规则见 [兼容与演进](./architecture.md#兼容与演进)。

### 自定义界面打不开或只看到旧布局

核对运行的原生宿主是否包含 HTML 资源协议、SDK 和子框 IPC 隔离改动，再核对已安装插件版本及 UI 文档哈希。旧宿主会拒绝未知 UI 字段；相同开发版本号不等于相同实现提交。重启并重新编译 Rust 宿主、更新当前插件，单纯刷新前端不能更新原生进程。新清单未安装时，旧包仍会显示旧界面。

界面连接失败保留会话，可从“扩展工具”重新加载界面；已报告的检查点和字段会恢复，不重新执行 Wasm 初始化。持续失败应检查 UTF-8、`ui.document` 引用、文档哈希、授权和 CSP，不删除注册表或私有存储，不放开远程脚本来绕过。独立窗口有语言与主题入口，可跟随宿主语言；默认样式和字体由 SDK 注入，插件自己的 CSS 可以覆写。工具菜单没有返回扩展中心操作，主窗口使用宿主导航。

当前工具入口在左侧当前扩展导航项右端，折叠图标栏时放在当前扩展图标下方；独立窗口入口在标题栏的主题按钮与最小化之间，左侧显示扩展图标和名称，正文不另显示宿主扩展标题行。骨架对应真实加载与首轮主题呈现，不是固定延时；首屏握手停滞时提供重试，后台或离屏不按前台等待误报。核对是否已有有效视图和新原生 SDK，不手工伪造内部呈现通知。握手只确认渲染机会，若已展示但正文异常，仍需排查作者脚本；它不检测全部业务错误，也不是服务 RPC 的统一超时。

下拉框仍使用原来的 select 值和事件，普通单选默认增强；作者 CSS 可覆写，需要系统原生行为时设 `data-starter-select="native"`，不修改全局原型。完整语义见 [自定义界面开发](./development.md#自定义界面开发)。

### 已推送分支但市场仍是旧内容

客户端只读取配置仓库的公开 latest Release。核对 `main` 是否已经合并、发布工作流是否成功、草稿是否公开并标为 latest，以及 `catalog.json` 和全部包是否已上传。更新本地子模块、推送功能分支、创建 PR、通过离线验签都不会更新该地址。

可先用以下只读命令检查远端状态，仓库名按 [listings.json](../listings.json) 的实际值替换：

```sh
gh release view --repo YanChao001/tauri-desktop-starter-extensions --json tagName,isDraft,isPrerelease,targetCommitish,publishedAt,assets
gh workflow list --repo YanChao001/tauri-desktop-starter-extensions
```

不要把某次排障时观察到的线上标签写成永久规则；每次都核对实际 Release。客户端普通读取有短期缓存，显式刷新可重新获取；下载前也会重新检查当前目录。网络失败时展示的旧已验证内容，不意味着当前下载与安装一定可用，过期目录不会继续获得安装资格。

### 签名有效但包校验失败

目录同时记录完整 JSON 包的 `packageSha256` / `packageBytes` 与内含 Wasm 的哈希和大小；任意一层不符都会拒绝安装。常见原因是签名后重新打包、格式化 JSON、上传了同名旧附件，或清单与编译产物不同。

先对完整发布目录运行 `node scripts/verify.mjs <目录>`，核对所有包而非只核对 Wasm。失败时从已审核源码重新构建并发布更高修订号，保留原目录供比较。不要在客户端重新计算一个“期望哈希”来接受变化，也不要覆盖已公开同修订目录。

签名前还会比对已审核 checkout 中的清单和 HTML 源文件，并检查包内预览及规范序列化；只调整完整包哈希不能通过。输入文件或祖先含符号链接 / junction、UTF-8 无效、Base64 不规范、文件越界时会拒绝。已有 `catalog.json` 也不会被签名脚本覆盖；需要重新签署时选择更高修订重新构建。

### 时间、过期与目录回退

确认设备 UTC 时间和时区设置正确。时区只影响显示；签名使用 Unix 秒。`expiresAt` 已到期报告 `MARKET_EXPIRED`，签发时间过远、期限颠倒或超过允许窗口属于 `MARKET_INVALID`。

同一仓库和公钥的客户端会跨重启保留最高修订号及 payload 摘要。将旧 Release 设为 latest、重新签署同修订目录、仅修改有效期或推荐标记，均可能触发拒绝。修复是发布更高修订号的完整目录，不删除信任状态、不倒拨时钟、不关闭验签。

## 原生服务与插件功能

### 新权限或服务不可用

局域网信使需要 `messaging:lan`，本机图库需要 `wallpapers:manage`；壁纸搜索、图片获取、来源外链和系统代理分别需要可选 `network:https`、`network:images`、`links:open`、`network:system-proxy`。核对已安装清单、实际授权、启用状态，以及运行的 Rust 宿主是否包含对应 effect / 固定服务和 SDK。拒绝可选权限不应阻塞本机图库。只更新市场脚本、浏览器前端或版本字符串不会补上原生实现；旧宿主可能在清单校验时直接拒绝。

服务请求绑定当前原生窗口与安装代次。禁用、撤权、替换或重装后，重新打开当前包，不重用旧页面的服务句柄。已完成的保存、发送或图片操作不会因前端停止等待而自动回滚；失败后先核对实际状态，不能自动重放有副作用的请求。

### LAN 监听或连接失败

按 [信使说明](../plugins/lan-chat/README.md#两台设备开始聊天) 在双方明确启动监听，输入对方实际显示的数字私有 IPv4 和端口。默认路由未选出可用私有 IPv4 时只绑定回环地址，只能本机使用；`127.0.0.1` 不是另一台电脑的地址。端口占用时先停止，再换未使用端口启动；网卡路由、防火墙和无线隔离由用户检查，插件不会提权或修改防火墙。

没有 UDP 扫描、自动发现、公网中继或域名连接。联系人须经真实握手后出现；“已写入连接，等待回执”不是已送达，对方原子保存后的 ACK 才确认送达。未得到回执时保留消息与送达状态；本地发送失败保留输入，先确认对方历史，避免重复发送。此协议为明文且无远端身份认证，不应用于秘密信息。

### 切换页面后仍然收信

这是原生服务的预期生命周期：导航和 iframe 重载不关闭已经明确开启的监听。界面只在可见时轮询状态，后台连接归属于使用该服务的原生窗口。需要停止时点击“停止监听与连接”；最后一个相关原生窗口关闭、撤权、更换 / 卸载插件或退出应用也会回收。停止连接保留联系人和历史，不能靠删除存档停止正在运行的服务。

状态查询应静默刷新，不应周期性禁用昵称、草稿、发送或连接按钮。出现打字卡顿、输入被旧内容替换或等待轮询才能操作时，核对已安装信使包和原生 SDK 是否更新；这不表示 TCP 必须停止。反馈中注明是后台查询还是手动请求，并保留可复现的延迟 / 乱序条件。

### 必应搜索、预览或下载失败

先核对宿主和插件配套：0.1.6 宿主不再提供供应商搜索，旧开发态壁纸库 1.0.2 的网络操作需要升级到 1.0.3；图库与背景设置没有 schema 迁移，不删除数据。新的搜索 URL、HTML 解析、查询匹配及来源解释由插件 Wasm 负责，通过已声明 `https://cn.bing.com` GET 的 HTTP effect 执行；默认搜索必应图片且不按许可筛选。Bing 网页改版、验证码或限流可能阻止解析，不能把请求成功但未解析到图片当作搜索成功。

区分搜索网页请求失败、插件解析失败、图片获取失败、资源失效和解码 / 额度拒绝。图片使用独立 `resources` 服务获取，`resourceId` 只在当前安装身份和原生窗口内有效，10 分钟过期；关闭、撤权或替换后重新获取资源，不能重用会话中的句柄。宿主不再接受旧 `resultId` / Commons `pageId`，也不为必应来源或图片许可背书。

先检查页面当前连接选项：初次打开时，已授予 `network:system-proxy` 则选择“跟随系统代理”，否则“直接连接”，合法且仍有授权的检查点偏好优先恢复。宿主请求省略模式时默认直连并禁用代理；选择系统代理仍须满足搜索或图片基础授权。系统模式使用锁定 reqwest 支持的用户系统 / 环境代理规则，没有匹配代理或被 `NO_PROXY` 排除时也走直连。插件不接收代理 URL，不能关闭 TLS，不承诺任意 PAC；该传输选择同时适用于获授权的普通 HTTP 和图片资源，不用于本机来源。

实际直连对该次目标域名的全部 DNS 结果执行公网校验并固定地址。`198.18.0.0/15` 等 Fake-IP、保留地址或其他非公网结果会拒绝；可为搜索与图片站配置真实公网 DNS，或使用已正确配置且由代理解析目标的系统代理，不能关闭校验。用户代理本身可在本机 / 内网；远端解析时应用不能证明最终 IP，仍保留 HTTPS、证书、禁止重定向与内容额度，详见 [连接说明](../plugins/wallpaper-browser/README.md#网络连接)。

浏览器能打开原站不表示原生使用相同传输。分别记录搜索 HTTP、图片获取、预览、另存与压缩导入的实际结果；服务替身、占位图或预先准备图片的解码不能冒充公网成功。当前分层验收与已移除的旧联网测试说明见 [服务验收](./testing.md#固定原生服务验收)。

图片获取仅接受符合公共 HTTPS、字节、MIME、JPEG / PNG / WebP 真实解码、尺寸和像素限制的内容。原站可能移除文件、要求 Cookie、返回跳转或提供其他格式，均不能为下载成功而绕过校验。资源预算已满时释放不用的资源后重试；系统另存取消是正常结果，不能标记为已保存。

### 图片已加入图库但不是原始文件

“加入图库”将有效图片资源交给图库服务重绘压缩，符合现有图库数量和单图额度；“下载原图”通过通用资源服务另存已验证的原始文件，两者不同。图库服务不下载供应商 URL，不再有 Commons 兼容路径。设置背景只影响本应用；当前插件不提供操作系统桌面壁纸能力。

图库已满或设置 revision 冲突时保留现有图片和其他偏好，刷新后再选择。移除正在使用的背景需确认并恢复纯色，不通过清空整个图库或偏好文件修复。更多规则见 [壁纸说明](../plugins/wallpaper-browser/README.md)。

### 游戏没有声音或返回后暂停

音效需要用户点击后解锁 Web Audio，先检查静音按钮和系统音量。环境不支持音频时贪吃蛇仍可正常游玩。失焦、隐藏和长帧会暂停；返回后手动继续，不补算离开期间的逻辑步。保存取消不清空棋局，长期保留请从宿主工具导出会话，纪录保存与棋局备份不是同一操作。

## 本地构建与真实 Wasm 校验

### 找不到 `extension-tool`

`STARTER_EXTENSION_TOOL` 必须是现有 `extension-tool` / `extension-tool.exe` 的绝对路径，不能指向桌面主程序、脚本或任意重命名工具。子模块布局可自动探测宿主的 debug 路径；独立市场检出必须显式指定。按 [开发指南](./development.md) 先准备平台依赖、构建宿主前端资源，再构建 CLI。

切换宿主源码后重新构建 CLI，不能只将环境变量指向旧二进制。如果 `expectJsonSubset`、清单字段或输出格式被报告未知，先核对工具对应的宿主提交是否具备该协议和 fixture 功能，避免删除断言来让旧工具通过。

### Rust 目标或插件产物缺失

使用 [rust-toolchain.toml](../rust-toolchain.toml) 指定的工具链，并为该工具链安装 `wasm32-unknown-unknown`。在市场仓库执行 `rustup target add wasm32-unknown-unknown`；如环境显式设置 `RUSTUP_TOOLCHAIN`，确认没有选到另一工具链。`build.json` 中的 `.wasm` 文件名须与该插件 Cargo 库名对应，构建脚本从各插件独立的 target 目录取产物。

锁文件、格式或源代码错误应直接修复，再运行 `check.mjs`。不要移除 `--locked`、删除所有锁文件或手工复制旧 Wasm 规避失败。ABI、资源或视图校验错误需要按宿主返回的阶段和消息修复，不改为跳过真实运行。

### 已存在相同修订目录

`Release directory already exists` 表示 `dist/market-<revision>` 已存在，脚本不会覆盖。先保留并核对旧产物，再选择新的本地检查修订号。正式发布修订还必须高于已有非草稿 Release 和已被客户端接受的最高修订号；仅换目录名不能改变已签名 payload 的 revision。

## CI 与生产发布

### 宿主工具准备长时间没有进展

展开 `host-tool` 复合步骤，按日志时间戳区分系统依赖安装、pnpm 初始化和 Rust 编译；整个复合步骤的耗时不代表当前子步骤的耗时。APT 日志反复出现 Azure 镜像的 `Ign` 时，优先检查镜像下载，不要直接归因于 pnpm 或 Rust。

市场 [宿主工具 action](../.github/actions/host-tool/action.yml) 使用 Ubuntu 官方 HTTPS 镜像，并限制连接等待、重试及整段 APT 安装时间。超时会明确失败；核对上游连接与完整日志后重跑，不跳过系统依赖或后续 Wasm 校验。

### PR CI 使用了旧宿主或无法检出 ref

PR / main CI 使用 `STARTER_HOST_REF` 仓库变量，默认是 `develop`；发布工作流的 `host_ref` 输入不会影响 PR。查看 Actions 摘要记录的实际宿主 SHA。协议修改尚未进入默认分支时，先推送并审核所需宿主提交，配置该变量后重跑 CI。

生产发布报 `Production host ref must be a reviewed, remotely available 40-character commit SHA` 时，在发布输入或仓库变量中提供已审核、已经推送的完整宿主 SHA；发布不接受分支、标签或空值。`revision` 必须使用十进制正 `u32`，科学计数法、十六进制、空白或越界输入在构建前拒绝，前导零会规范化。

本地未推送的 SHA、拼错的分支、不可读仓库或已移除的 ref 都会导致检出失败。修正远端可读的固定提交及权限，不能用本机产物替代 CI 的源码来源。独立 CI 会安装宿主 Linux 依赖并准备前端构建；某平台通过不能替代其他目标系统的运行验收。

### 生产 Secret 缺失或与公钥不匹配

`Signing key does not match public-key.txt` 表示没有提供私钥，或提供的有效私钥与受审阅公钥不是一对。若传入的 PEM 内容不完整或格式无效，Node 密钥解析会直接报错，不一定出现该错配消息；`MARKET_KEY_FILE` 路径不存在或不可读也会直接报告文件错误。本地签名可通过该变量读取仓库外 PKCS#8 PEM 私钥文件。按具体错误分别检查 Secret 是否配置、文件是否可读、PEM 格式和公钥对应关系，不将值打印到日志、issue、命令行或聊天。

普通 PR / `check.mjs` 不需要该 Secret，其成功不能证明生产签名配置可用。不要为通过发布而随意替换公钥；真正轮换需同步宿主信任配置和升级计划，见 [公钥轮换](./publishing.md#下架回退与公钥轮换)。

### revision 重复或发布目标 SHA 错误

`Market revision must increase` 表示新修订没有高于脚本分页读取的全部非草稿 Release 中的 `market-*` 修订。选取更高修订，从构建开始重新执行；客户端还可能见过现已删除的更高修订，维护者需要结合发布记录判断。历史 API 读取失败或结构异常会在创建草稿前拒绝，不能忽略错误或退回只看最近一页。

`Release source must be a complete 40-character commit SHA` 表示发布没有可靠的源码身份。Actions 使用市场仓库的 `GITHUB_SHA`；本地必须提供 `MARKET_SOURCE_SHA`。若两个变量同时存在，前者优先。核对 SHA 已在远端存在，并对应包的已审核市场源码，不使用宿主 SHA、短 SHA 或可变分支名。

`Release tag does not match the reviewed source commit` 表示拟发布的同名标签实际指向另一提交，`--target` 不会覆盖它。脚本在创建草稿前和公开为 latest 前分别检查，包括带注释标签的最终 commit；异常结构、无法解引用或读取失败也会阻止继续。先核对标签历史和已审核来源，使用未占用的更高修订重新构建，或由维护者按已确认的草稿恢复方案处理。不要强制移动已经公开使用的标签，也不要把 API 错误忽略为“不存在”。

### 上传失败或只看到草稿

脚本先创建 draft，再上传全部附件，最后才公开并设置 latest。网络、附件冲突或权限失败时草稿可能仍在。检查运行日志、草稿及完整附件，按 [发布流程](./publishing.md#actions-生产发布) 处理，不能手动公开不完整草稿来消除错误。

如果包已公开后发现问题，用更高修订目录下架或修复。不要覆盖公开附件、降低修订或宣称删除 Release 会卸载用户已安装插件。

## 数据保留与求助

市场读取或下载失败不需要删除扩展注册表、私有存储、系统凭据或信任记录。旧开发版扩展注册表使用宿主提供的确认归档流程；损坏、未来版本和未知数据保留原件，不能假定为可重建旧版本。不要在应用仍使用目录时从外部搬动它。

普通 bug 报告提供错误码、版本、提交 / Release、复现步骤和脱敏日志。涉及签名绕过、恶意包或密钥泄露时，按 [安全规范](./security.md#漏洞与密钥事件) 私密报告。记录已完成的检查与未验证范围，不把浏览器 mock、离线 fixture、CI 配置或本地签名当成真实桌面及线上发布成功。
