# 市场与插件安全规范

市场收录意味着维护者审核并分发一个包，不意味着代码天然可信或用户已授予权限。开发、审核和发布分别承担不同责任；操作流程见 [发布与维护](./publishing.md)，故障处理见 [排障手册](./troubleshooting.md)。

## 信任与职责

| 边界                 | 负责方     | 必须保证的内容                                                                   |
| -------------------- | ---------- | -------------------------------------------------------------------------------- |
| 插件逻辑、状态与输入 | 插件作者   | 校验动作、字段、导入状态和效果回执；为业务不变量和异常路径编写测试               |
| 收录与分发           | 市场维护者 | 审核源码、来源、许可证、依赖、权限和生成产物；保护签名私钥；按期续签和处理下架   |
| 安装与能力执行       | 宿主       | 验签、版本及哈希检查、安装身份、授权、网络和存储边界、调度、超时、取消及视图解析 |
| 启用与主动发送       | 用户       | 审阅来源和权限，决定是否启用、授予可选能力、发送所选数据或保存产物               |

目录签名认证的是受信发布密钥及已签名 payload 的完整性。清单中的 `author` 是作者提供的元数据，签名不证明作者真实身份，也不能代替源码审核。市场来源收据绑定仓库、公钥指纹、目录修订和完整包哈希；本地导入包不能自行声明该身份。

宿主校验仍是最终执行边界。市场 JavaScript 检查用于签名前审核，不能取代 Rust 的清单、ABI、视图与运行时检查，也不能通过增加一个前端 capability 就获得 Wasm 权限。

## 插件审核

提交收录前审阅实际源码和锁文件，确认包 ID、语义版本、作者说明、许可、入口、所需能力与功能相符。依赖应有明确用途、可信来源和可接受许可证；新增网络、存储、文件输入或凭据使用必须说明用途、数据范围与失败行为。不得以一个通过的 smoke fixture 代替完整代码审核。

- 优先将增强功能声明为可选权限，让未授权用户仍能使用离线部分。每条命令声明启动门槛；授权主体是整个插件，不能把命令门槛误认为该命令运行后的权限上限。
- 不依赖宿主界面已经验证输入。插件仍需限制集合长度、数字和日期范围、枚举、索引、状态版本、历史与导入数据，避免构造状态绕过业务规则。
- 所有 `host-result` 都核对效果 ID、值和结构化错误。存储使用宿主快照的 revision，冲突时保留草稿并提示重新读取，不静默覆盖其他窗口。
- 效果批次不是事务；取消、超时或后续视图错误不代表已经执行的写入和网络操作被撤销。不自动重试有副作用的请求，尤其注意“操作已完成但响应过大被省略”的回执。
- 导出采用受限产物，文件名和内容按实际格式校验，不接受宿主路径。Markdown、表格、HTML 特殊字符和 CSV 公式前缀按各输出用途处理，不把用户文本拼接为可执行内容。
- 真实运行、权限拒绝、旧状态或损坏状态、存储冲突和取消应有明确可理解的结果；拒绝权限后不伪造持久化或后台成功。

精确协议、额度和运行边界由配套宿主的[扩展指南](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md)及源码维护，市场文档不另建一套协议定义。

## 执行隔离与数据能力

插件业务交付 Extism Wasm；Rust、JavaScript 和 TypeScript 是构建来源，用户运行时无需安装这些工具。界面可采用通用视图或包内单文件 HTML / CSS / JavaScript，框架需构建为本地单文件。宿主不执行 Node.js、原生插件程序或远程网页。

自定义 UI 使用无同源权限的 sandbox frame、独立 CSP 和受限消息桥。原生专用协议验证窗口、租约、当前安装代次、授权与 UI 哈希；带密钥的 IPC 发送入口仅安装到顶层宿主，显式处理 WebView2 子框注入。文档启动脚本锁定 WebRTC，CSP 禁止远程脚本、直接网络、子框和 worker。UI 只能操作本会话字段 / 检查点、请求当前 Wasm 动作和保存当前产物，不接受任意命令名或路径；网络、私有存储与凭据仍经受控 effects。

HTML 同样属于被审核的可执行源码：使用安全文本节点处理外部内容，检查点报告真实未保存状态，输入和关闭流程需验证键盘、取消与窄屏。UI 脚本不受 Wasm 的计算 / 内存预算覆盖，隔离不等于 UI 进程资源沙箱。宿主测试中使用的假协议与对话框不证明原生注入已经验收。

Wasm 限制可用导入、线性内存、执行预算和输出，worker 子进程提供终止与故障恢复。worker 仍以当前用户身份运行，**不是额外的操作系统权限沙箱**。因此仍须审计 Wasmtime / Extism、宿主 broker、进程协议和平台配置，不能声称“使用 Wasm 就可以免审任何代码”。

文件内容仅来自用户显式选择和发送，不提供原始路径。网络来源和方法须在清单声明并获授权；公网 HTTPS 与本机服务是不同能力，不能以本机权限访问任意内网。系统凭据由宿主保管并按扩展、来源和别名注入，插件不能读取秘密原文。宿主限制不等于业务数据已脱敏，插件仍须在功能说明中交代哪些内容会发送到哪个服务。

私有存储按插件 ID 隔离，卸载默认保留用户数据。同 ID 重装后，用户重新授予存储能力即可访问原有空间；不要复用另一产品的 ID，也不要把私有存储视为凭据库或完整备份。会话导出可能包含用户输入、草稿和插件状态，分享前应由用户审阅，不自动上传或附在公开 issue。

## 密钥与构建隔离

生产私钥只进入受控 GitHub Secret `MARKET_SIGNING_PRIVATE_KEY`，或仓库外的受保护文件，经 `MARKET_KEY_FILE` 指定。公钥 `public-key.txt` 可以公开；私钥、令牌、真实凭据、用户存档和含敏感内容的日志不得提交，包括误提交后再删除的历史。

普通开发与 PR 检查不需要私钥：`check.mjs` 使用仅驻留内存的一次性 Ed25519 密钥执行离线验签。构建脚本向 Cargo 和宿主工具传递的环境会移除 `MARKET_SIGNING_PRIVATE_KEY` 与 `MARKET_KEY_FILE`。生产 Actions 将构建和签名放在独立 job 中，生产密钥仅注入不执行插件构建的签名步骤，签名前再次核对已审核清单与包哈希。

这不代表任意构建脚本都安全：Cargo 构建依赖和工具链代码会在构建机执行。审核依赖变更，不向开发或构建进程提供无关凭据，不在 Secret 可见环境中运行未经审阅的 PR。日志保留版本、哈希、错误码和必要上下文，避免输出私钥环境、Authorization、用户文件内容或完整会话。

目录续签、防回退、密钥轮换和上传失败的处理统一见 [发布与维护](./publishing.md)，不得通过关闭验签、接受过期目录、降低修订号或清除客户端信任记录恢复发布。

## 漏洞与密钥事件

安全报告渠道以宿主仓库的 [SECURITY.md](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/SECURITY.md) 为准。不要在公开 issue、PR 或 Actions 日志披露漏洞利用细节、私钥、令牌或真实用户数据。若私密漏洞报告入口尚不可用，先通过维护者已公开的联系方式请求私密渠道，确认后再提交详情，不编造安全邮箱或把公开 issue 当作私密工单。

报告尽量提供受影响的宿主和市场提交、插件 ID / 版本、系统平台、最小复现、稳定错误码与影响范围；复现使用脱敏的合成数据。遇到疑似恶意包、密钥泄露或签名链问题时保留可验证的包哈希、目录 payload 和发布时间证据，立即私下联系维护者，避免公开传播秘密。

维护者应评估受影响目录与用户范围，必要时撤销相关发布凭据、轮换密钥、发布更高修订号的修复目录并提供处置说明。下架只阻止新的市场下载，不能撤回已经安装或复制的包；需要用户禁用、卸载或升级时，应明确通知，不能宣称远程清理已经完成。
