# 市场与插件安全规范

市场收录意味着维护者审核并分发一个包，不意味着代码天然可信或用户已授予权限。开发、审核和发布分别承担不同责任；操作流程见 [发布与维护](./publishing.md)，故障处理见 [排障手册](./troubleshooting.md)。

## 信任与职责

| 边界                 | 负责方     | 必须保证的内容                                                                   |
| -------------------- | ---------- | -------------------------------------------------------------------------------- |
| 插件逻辑、状态与输入 | 插件作者   | 校验动作、字段、导入状态和效果回执；为业务不变量和异常路径编写测试               |
| 收录与分发           | 市场维护者 | 审核源码、来源、许可证、依赖、权限和生成产物；保护签名私钥；按期续签和处理下架   |
| 安装与能力执行       | 宿主       | 验签、版本及哈希检查、安装身份、授权、网络和存储边界、调度、超时、取消及视图解析 |
| 启用与主动发送       | 用户       | 审阅来源和权限，决定是否启用、授予可选能力、发送所选数据或保存产物               |

目录签名认证的是受信发布密钥及已签名 payload 的完整性。清单中的 `author` 是作者提供的元数据，签名不证明作者真实身份，也不能代替源码审核。市场来源收据绑定仓库、公钥指纹、目录修订和完整包哈希；本地导入包不能自行声明该身份。

未来条目隔离只限制可用资格，不放宽完整目录的签名、元数据与防回退检查，不能下载或安装不兼容条目。适用版本和严格条件统一见 [架构说明](./architecture.md#兼容与演进)。

宿主校验仍是最终执行边界。市场 JavaScript 检查用于签名前审核，不能取代 Rust 的清单、ABI、视图与运行时检查，也不能通过增加一个前端 capability 就获得 Wasm 权限。

## 插件审核

提交收录前审阅实际源码和锁文件，确认包 ID、语义版本、作者说明、许可、入口、所需能力与功能相符。依赖应有明确用途、可信来源和可接受许可证；新增网络、存储、文件输入或凭据使用必须说明用途、数据范围与失败行为。不得以一个通过的 smoke fixture 代替完整代码审核。

- 优先将增强功能声明为可选权限，让未授权用户仍能使用离线部分。每条命令声明启动门槛；授权主体是整个插件，不能把命令门槛误认为该命令运行后的权限上限。
- 不依赖宿主界面已经验证输入。插件仍需限制集合长度、数字和日期范围、枚举、索引、状态版本、历史与导入数据，避免构造状态绕过业务规则。
- 所有 `host-result` 都核对效果 ID、值和结构化错误。存储使用宿主快照的 revision，冲突时保留草稿并提示重新读取，不静默覆盖其他窗口。
- 效果批次不是事务；取消、超时或后续视图错误不代表已经执行的写入和网络操作被撤销。不自动重试有副作用的请求，尤其注意“操作已完成但响应过大被省略”的回执。
- 导出采用受限产物，文件名和内容按实际格式校验，不接受宿主路径。Markdown、表格、HTML 特殊字符和 CSV 公式前缀按各输出用途处理，不把用户文本拼接为可执行内容。
- 真实运行、权限拒绝、旧状态或损坏状态、存储冲突和取消应有明确可理解的结果；拒绝权限后不伪造持久化或后台成功。

精确协议、额度和运行边界由配套宿主的[扩展指南](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md)及源码维护，市场文档不另建一套协议定义。

## 执行隔离与数据能力

插件业务交付 Extism Wasm；Rust、JavaScript 和 TypeScript 是构建来源，用户运行时无需安装这些工具。界面可采用通用视图或包内单文件 HTML / CSS / JavaScript，框架需构建为本地单文件。宿主不执行 Node.js、原生插件程序或远程网页。

自定义 UI 通过无同源权限的 sandbox、独立 CSP 与受限消息桥隔离，只操作当前会话、请求本命令动作、保存产物和使用获授权的固定服务；通用网络、KV 与凭据经受控 effects。审核 HTML 时保留此边界，使用 SDK，避免直接原生 IPC、宿主 DOM、远程脚本或网络。平台注入、消息身份和 CSP 的准确规则见 [宿主自定义界面](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md#自定义界面)。

HTML 同样属于被审核的可执行源码：使用安全文本节点处理外部内容，检查点报告真实未保存状态，输入和关闭流程需验证键盘、取消与窄屏。UI 脚本不受 Wasm 的计算 / 内存预算覆盖，隔离不等于 UI 进程资源沙箱。宿主测试中使用的假协议与对话框不证明原生注入已经验收。

Wasm 限制可用导入、线性内存、执行预算和输出，worker 子进程提供终止与故障恢复。worker 仍以当前用户身份运行，**不是额外的操作系统权限沙箱**。因此仍须审计 Wasmtime / Extism、宿主 broker、进程协议和平台配置，不能声称“使用 Wasm 就可以免审任何代码”。

文件内容仅来自用户显式选择和发送，不提供原始路径。普通 HTTP effect 的来源和方法须在清单声明并获授权；通用图片资源另用独立 `network:images`，允许任意公共 HTTPS GET 图片，不是逐站来源白名单。公网 HTTPS 与本机服务是不同能力，不能以本机权限访问任意内网。系统凭据由宿主保管并按扩展、来源和别名注入，插件不能读取秘密原文。宿主限制不等于业务数据已脱敏，插件仍须在功能说明中交代哪些内容会发送到哪个服务，包括图片 URL 的查询参数。

私有存储按插件 ID 隔离，卸载默认保留用户数据。同 ID 重装后，用户重新授予存储能力即可访问原有空间；不要复用另一产品的 ID，也不要把私有存储视为凭据库或完整备份。会话导出可能包含用户输入、草稿和插件状态，分享前应由用户审阅，不自动上传或附在公开 issue。

## 原生服务与外部来源

固定服务为 `lan`、`wallpaper`、`resources`、`links` 和 `window`，请求由宿主补充插件身份、模块哈希、安装代次和原生窗口，逐次核对启用、授权及生命周期。它们分别核验 `messaging:lan`、`wallpapers:manage`、`network:images`、`links:open` 和 `window:control`，不能将任何一种权限当作任意 IPC、路径或系统命令能力。`window` 仅允许读取、设置调用插件独立原生窗口的置顶状态，不接受 label，嵌入主界面不能控制宿主窗口，完整规则见 [宿主自身窗口服务](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md#插件自身窗口)。撤权与安装变更通过原生服务门闩协商，停止等待不代表此前副作用回滚。

**LAN** 仅连接用户明确输入的数字私有 / 回环或允许的本地链路 IP，不接受公网、域名或任意 URL，不扫描网络、不修改系统防火墙。TCP 消息与附件为明文，没有端到端加密和远端身份认证，昵称及节点身份由对方声明；只适用于可信局域网设备，不发送秘密或误称“安全会话”。写入连接与对端持久保存回执是不同状态。本机回环模式在 `127.0.0.1` 创建真实 TCP 节点与助手，仅验证当前设备链路，不证明跨设备网络可达。

`messaging:lan` 允许有界图片 / 文件传输与私有缓存，不等于任意文件读取。发送与另存均经原生系统对话框选择，不接受插件或远端传入系统路径，不自动打开或执行文件。图片需真实解码并生成受控预览；普通文件只展示元数据卡片。单文件与总缓存额度、路径 / 链接校验、协议及存档版本以 [宿主 LAN 边界](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md#局域网通信) 为准。会话文本导出只保留附件标签，不嵌入文件字节。

联系人和历史由原生服务按插件隔离，链接、损坏或未来存档保留原件并拒写；与普通插件 KV 分开。连接属于原生窗口，导航后继续接收，会话导入不自动重连或发送。停止、窗口关闭及撤权回收见 [内网通信说明](../plugins/lan-chat/README.md#信任边界与数据)。

**图源与来源** 属于插件业务。壁纸库 Wasm 通过声明并授权的 HTTPS GET 来源请求图片 API，校验输入、响应、图片身份和匹配回执，失败保留原成功筛选。具体来源与批量规则见 [壁纸说明](../plugins/wallpaper-browser/README.md#图源预览与资源)。免费接口和 SFW 标签不代表图片使用许可；宿主核验通用网络、内容与能力边界，不认证原作归属。

**图片资源** 使用独立的可选 `network:images`。它允许插件提交任意公共 HTTPS URL 进行 GET，图片 URL 的查询参数也能携带数据，因此必须审阅其发送用途，不能将此权限描述为仅读取搜索结果或仅本机图片。宿主限制 HTTPS、正常证书、禁止重定向、响应字节、MIME 与真实解码；只发送固定应用 User-Agent，不开放 Cookie、插件自定义图片请求头或任意代理地址。成功资源返回短期不透明 `resourceId` 与内容元数据，预览返回安全 data URL，另存使用系统对话框且不暴露路径。

资源绑定插件、模块哈希、安装代次和原生窗口，受有效期、数量、字节及解码额度限制。关闭、撤权或安装变更清理关联资源；跨窗口、伪造、过期与旧安装句柄拒绝，导入会话不恢复资源资格。精确额度统一见 [宿主图片资源边界](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md#壁纸图库与图片搜索)。

**网络传输** 继承宿主连接设置时仍检查插件独立代理授权，代理权限不能替代基础网络授权或清单来源 / 方法。插件不指定代理地址或关闭 TLS。省略与显式 `networkMode`、授权回落、本机来源、系统代理及排除规则由 [宿主来源与授权](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/docs/extensions.md#来源与授权) 统一定义，用户操作见 [网络连接](../plugins/wallpaper-browser/README.md#网络连接)。

公共 HTTPS 直连核验全部解析地址并固定连接目标，拒绝 Fake-IP 等非公网地址；被代理排除后同样执行直连检查，`network:local` 只按其本机来源规则工作。代理服务器可以位于本机或内网，由代理远端解析时宿主无法证明最终目标 IP，仍保留 HTTPS、证书、禁止重定向和内容限制。审核与交付不得把这一路径描述为已完成最终公网 IP 校验。

**图库与外链** 各有独立边界。`wallpapers:manage` 只管理现有图库和背景设置，远程内容经有效资源句柄重绘压缩后导入并执行图库配额，原图另存不由图库服务提供。背景写入既有设置并执行 revision CAS，不改变操作系统桌面壁纸；移除当前背景及失败恢复不能清空其他偏好。`links:open` 只允许通过系统浏览器打开经 URL 校验的公共 HTTPS 名称，拒绝本机名称、IP 字面量、其他协议或系统命令；最终 DNS 和连接由浏览器负责，不能声称宿主控制了浏览器解析或证明页面可信。拒绝可选图源 API、图片、外链或代理权限，不阻塞本机图库。

## 密钥与构建隔离

生产私钥只进入受控 GitHub Secret `MARKET_SIGNING_PRIVATE_KEY`，或仓库外的受保护文件，经 `MARKET_KEY_FILE` 指定。公钥 `public-key.txt` 可以公开；私钥、令牌、真实凭据、用户存档和含敏感内容的日志不得提交，包括误提交后再删除的历史。

普通开发与 PR 检查不需要私钥：`check.mjs` 使用仅驻留内存的一次性 Ed25519 密钥执行离线验签。构建脚本向 Cargo 和宿主工具传递的环境会移除 `MARKET_SIGNING_PRIVATE_KEY` 与 `MARKET_KEY_FILE`。生产 Actions 将构建和签名放在独立 job 中，生产密钥仅注入不执行插件构建的签名步骤，签名前再次核对已审核清单与包哈希。

签名和发布读取有界、严格 UTF-8 的文件，不接受输入文件或其祖先中的符号链接 / junction。签名前核对包内清单、模块、UI 与已审核 HTML 来源；签名目录及完整附件通过验证后，发布仅上传本次新建临时目录中的字节快照。规范 Base64、密钥与签名包头、完整包字节和字段结构都参与检查，不能依靠 Node 的宽松解码接受宿主会拒绝的内容。

这不代表任意构建脚本都安全：Cargo 构建依赖和工具链代码会在构建机执行。审核依赖变更，不向开发或构建进程提供无关凭据，不在 Secret 可见环境中运行未经审阅的 PR。日志保留版本、哈希、错误码和必要上下文，避免输出私钥环境、Authorization、用户文件内容或完整会话。

市场工作流中的外部 Actions 固定到完整提交 SHA，旁注记录对应主版本；升级时核对上游仓库与提交，不直接恢复为可变标签。生产发布只接受已审核且远端可获取的宿主完整提交 SHA，PR 检查可使用开发分支；宿主工具和市场插件分别使用各自锁定的 Rust 工具链。

目录续签、防回退、密钥轮换和上传失败的处理统一见 [发布与维护](./publishing.md)，不得通过关闭验签、接受过期目录、降低修订号或清除客户端信任记录恢复发布。

## 漏洞与密钥事件

安全报告渠道以宿主仓库的 [SECURITY.md](https://github.com/YanChao001/tauri-desktop-starter/blob/develop/SECURITY.md) 为准。不要在公开 issue、PR 或 Actions 日志披露漏洞利用细节、私钥、令牌或真实用户数据。若私密漏洞报告入口尚不可用，先通过维护者已公开的联系方式请求私密渠道，确认后再提交详情，不编造安全邮箱或把公开 issue 当作私密工单。

报告尽量提供受影响的宿主和市场提交、插件 ID / 版本、系统平台、最小复现、稳定错误码与影响范围；复现使用脱敏的合成数据。遇到疑似恶意包、密钥泄露或签名链问题时保留可验证的包哈希、目录 payload 和发布时间证据，立即私下联系维护者，避免公开传播秘密。

维护者应评估受影响目录与用户范围，必要时撤销相关发布凭据、轮换密钥、发布更高修订号的修复目录并提供处置说明。下架只阻止新的市场下载，不能撤回已经安装或复制的包；需要用户禁用、卸载或升级时，应明确通知，不能宣称远程清理已经完成。
